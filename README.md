# MEGA Backup for Home Assistant

> [!WARNING]
> **This project was 100% vibe coded.** The code was generated by an AI assistant
> rather than written or reviewed by a human. It passes its test suite and was
> verified end to end against a real MEGA account, but it has not been audited by
> a security professional. Read the code before trusting it with your backups,
> and keep an independent copy of anything you cannot afford to lose.

Use a [MEGA](https://mega.nz) account as a backup location for Home Assistant.
The integration registers a backup agent, so MEGA appears next to the built-in
local and network locations in **Settings → System → Backups**.

## Features

- Store Home Assistant backups in any folder of your MEGA Cloud Drive.
- Backups created by Home Assistant, including automatic backups and backups
  protected with a password.
- List, download (restore) and delete backups from the Home Assistant UI.
- Two-factor authentication (TOTP) during setup.
- The MEGA session (and master key) is stored in the config entry, so restarts
  and reloads do not require a new 2FA code.
- Folders are created on demand, including nested paths such as
  `Backups/Home Assistant`.
- A free-space check stops an upload before it starts when the account is
  almost full.
- Reauthentication flow when the stored session or password stops working.

## Installation

### HACS

1. Make sure [HACS](https://hacs.xyz) is installed.
2. Add this repository as a custom repository of type **Integration**:
   **HACS → Integrations → ⋮ → Custom repositories**, using
   `https://github.com/viciousidiot/ha-mega-backup`.
3. Search for **MEGA Backup**, open it and choose **Download**.
4. Restart Home Assistant.

### Manual

Copy the `custom_components/mega_backup` directory into the
`custom_components` directory of your Home Assistant configuration and restart
Home Assistant.

## Configuration

1. Go to **Settings → Devices & services → Add integration**.
2. Search for **MEGA Backup**.
3. Enter your MEGA email address, password and the folder that should hold the
   backups. The default is `Home Assistant Backups`.
4. If the account has two-factor authentication enabled, enter the current code
   from your authenticator app.

The folder is resolved below the root of the MEGA Cloud Drive and created when it
does not exist. Nested folders can be separated with `/`. To store backups in an
existing shared folder, add that folder to your own Cloud Drive first.

After the integration is set up, open **Settings → System → Backups**, create a
backup and select the MEGA location. Automatic backups can be configured to use
the MEGA location as well under **Settings → System → Backups → Automatic
backups**.

The storage folder can be changed later through the integration's **Configure**
button.

## How backups are stored

Each backup is uploaded as two files in the configured folder:

| File | Contents |
| --- | --- |
| `<name>_<date>.tar` | The backup archive created by Home Assistant |
| `<name>_<date>.tar.metadata.json` | Home Assistant's backup metadata |

Home Assistant itself decides whether the archive is encrypted (backups
protected with a password are encrypted by Home Assistant before upload). MEGA
additionally encrypts all stored data with the account's keys.

Backups are identified by the `backup_id` inside the metadata file, not by the
file name. This keeps restores working when a file was renamed in the MEGA app.
Deleting a backup removes both files. Archives without a metadata sidecar (for
example files uploaded manually to the folder) are ignored and left untouched.

## Limitations

- The MEGA API is a third-party, undocumented API. MEGA can change it at any
  time; this integration implements the same protocol as the widely used
  `megajs` library.
- Listing backups downloads and reads every metadata file. This is fast for
  typical backup counts but adds a request per backup.
- MEGA applies transfer quotas and rate limits. Very large or very frequent
  backups can be throttled by MEGA; the integration retries temporary errors.
- On some networks MEGA answers API calls with `HTTP 402` plus an `X-Hashcash`
  proof-of-work challenge. The integration solves the challenge (one to two
  seconds) and repeats the request, then keeps using the solved token until MEGA
  asks again.
- Only the Cloud Drive is supported. The Rubbish Bin and Inbox are not used.
- Backups made outside this integration (without a metadata sidecar) cannot be
  restored through Home Assistant.

## Removal

Remove the integration entry, then delete the folder from the MEGA app if you no
longer need the backups. Removing the integration never deletes files by itself.

## Development

The integration is pure Python and has no third-party runtime dependencies
beyond Home Assistant itself: the MEGA client (`custom_components/mega_backup/client.py`)
is implemented with `aiohttp` and `cryptography`.

Run the test suite with:

```bash
python -m pip install -r requirements-test.txt
pytest
```

The tests start an in-process MEGA API emulator (`tests/fake_mega.py`) that
validates login hashes, RSA sessions, node key wrapping, chunked AES-CTR uploads
and meta MACs. No MEGA account or network access is required.

On Windows, create the environment with Python 3.14 and set `PYTHONPATH` to
include small `fcntl`/`resource` shims if the Home Assistant test harness needs
them; `conftest.py` already keeps sockets usable for the asyncio event loop.

### Verifying against a real account

`scripts/verify_live.py` runs the client and the backup agent end to end against
a real MEGA account. It uploads, lists, downloads (with MAC verification),
de-duplicates and deletes test backups, then removes the folders it created.

```bash
export MEGA_EMAIL="you@example.com"
export MEGA_PASSWORD="..."
python scripts/verify_live.py            # add --mfa <code> for 2FA accounts
```

Credentials can also live in a JSON file passed with `--creds <path>`. Use
`--keep` to leave the test folders on the account. The script is smoke tested
against the fake server in `tests/test_verify_script.py`.

Before publishing a fork, replace the `documentation`, `issue_tracker` and
`codeowners` values in `custom_components/mega_backup/manifest.json` with the
details of your own repository.
